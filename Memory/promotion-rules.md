# AI-Suplex Memory Promotion Rules

These rules define how extracted learnings move from temporary notes into durable memory.

## Promote to Semantic Memory

Promote a memory item to semantic if:
- it is repeatedly true across sessions,
- it reflects a durable rule, fact, or preference,
- it has not been contradicted by stronger evidence.

Examples:
- naming conventions,
- stable project priorities,
- user preferences,
- durable constraints.

## Promote to Procedural Memory

Promote a memory item to procedural if:
- it describes a repeatable workflow,
- the workflow has worked more than once,
- it improves execution quality or reduces friction.

Examples:
- how to generate a tasklist,
- how to run session start,
- how to write session end reports,
- how to promote lessons.

## Keep in Lessons

Keep a memory item in lessons if:
- it is useful,
- but evidence is not yet strong enough for long-term storage,
- or it may need more examples before promotion.

## Deprecate

Mark a memory item as deprecated if:
- a newer rule supersedes it,
- repeated evidence shows it is no longer correct,
- or it conflicts with a stronger, more recent pattern.

Deprecated items should be kept visible until a review cycle confirms replacement.

## Archive

Archive a memory item if:
- it is no longer relevant,
- it is historical only,
- or it should no longer influence execution.

## Default Bias

When in doubt:
- keep temporary,
- do not over-promote,
- prefer stable evidence over clever guesses,
- let repeated use determine importance.
